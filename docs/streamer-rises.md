# 配信者別の急上昇判定仕様

## 1. 目的

ゲーム単位の視聴者数変化を検出し、全体で急増しているゲームと「単一の配信者の急増によるもの」を区別して報告する。判定は共通化する。21時・23時のHTML（メールHTML本文・添付を含む）では時間帯別の前日比較枠を表示せず、メールplainには表示する。

## 2. 用語・定義

- **対象ゲーム**: 日本語配信の上位最大1,000配信のうち、IGDB IDが登録されたゲーム。
- **比較元（before）/ 今回（after）**: 各時間帯ルールの比較対象時刻と観測時刻のデータ。
- **broadcasters 辞書**: ゲームごとの `Twitch user_id → 視聴者数` の辞書。比較元・今回それぞれについて保存する。
- **全体 before / after**: そのゲーム内で観測された配信者全体の視聴者数の合計。
- **増加寄与**: そのゲーム内の「配信者別人数差（今回 − 比較元）」の最大値。
  - 同差が複数の配信者にある場合は配信者IDの文字列順で選ぶ。寄与人数を全体の純増人数で割った寄与率も表示する。他の配信者が減少すると100％を超えることがある。
  - 観測範囲にいない配信者（broadcasters 辞書にキーがない配信者）は、観測合計への寄与を 0 とする。実際の視聴者数が 0 であると断定しない。
- **増加率**: `(after − before) / before`。

## 3. 判定条件

各対象ゲームについて、以下を順に評価する。

### 3.1 判定不能（率算出不能・欠測）

判定不能は、3.3 の 1（全体条件）を満たしたゲームだけに適用する。全体条件を満たさないゲームは、内訳の有無にかかわらず 3.5 の「該当なし」とする。

- 全体 `before = 0` の場合（`after > 0` を含む）は、全体の増加率が算出できず全体条件を満たさないため、判定不能ではなく**該当なし**（3.5）とする。いずれの枠にも選出せず、「判定不可：Nタイトル」の件数にも含めない。
- 全体条件を満たし、配信者別内訳（broadcasters）が比較元・今回のどちらかで未取得（欠測）の場合は、推測・移行を行わず**判定不能**とする。古い形式で game 合計のみの記録もこれに当たる。
- 全体条件を満たしても、除外後の比較元が0人で今回が正数なら、25％の増加率を算出できないため**判定不能**として両枠から除外する。
- 判定不能のゲームは通常・単一のいずれにも選出せず、「判定不可：Nタイトル」の件数に含める。

### 3.2 除外後の人数が両方0

- 全体の25％条件を満たしたうえで、最多寄与配信者を除いた残りが比較元・今回とも0人なら、**単一枠**に分類する。

### 3.3 通常急上昇

次の 1 と 2 の**両方**を満たす場合。

1. **全体条件**: 全体 `before > 0` かつ増加率が 25% 以上（`>= 25%`）。
2. **除外後条件**: 増加寄与が最大の配信者（同一の配信者 ID）を比較元・今回の両方から除いたうえで、
   - 除外後の before 残りが `> 0` であり、
   - 除外後の増加率が 25% 以上。

### 3.4 単一配信者による急増（別枠）

- 3.3 の 1（全体条件）を満たすが、2（除外後条件）を満たさない場合（3.1の欠測・率算出不能を除く）。
- 別枠「単一配信者による急増」として表示する。
- 各時間帯・各枠ごとに最大 3 件まで。
- 通常急上昇との重複を許さない（1 ゲームは 1 枠のみ）。
- 別枠に該当するゲームが 1 件もない場合は、その枠（セクション）を非表示とする。

### 3.5 該当なし

- 上記いずれにも該当しないゲーム（例: 全体条件を満たさない減少・横ばい・25％未満の増加、比較元0人からの増加）は、急上昇のどの枠にも選出せず、判定不可の件数にも含めない。

## 4. 分類後の並び順

各枠内の並びは、**元の全体増加人数の降順**、同数の場合は**ゲーム ID 順**。

## 5. データ取得・保存

### 5.1 取得

- 取得は従来どおりTwitchの視聴者数上位最大1,000配信。追加API呼び出しはせず、取得レスポンスのuser_idとviewer_countをゲームIDごとに合算する。
- 各対象ゲームについて、Twitch `user_id → viewers` の broadcasters 辞書を比較元・今回それぞれ取得して保存する。

### 5.2 SQLite

- 新規の子テーブル **`game_audiences`** に、broadcasters 辞書の JSON を記録する。
- 既存テーブルへのデータ変換は不要（既存表はそのまま）。
- 古い game 合計のみの記録はそのまま残るが、3.1 に従い選出されない（全体条件を満たす場合は判定不能、満たさない場合は該当なし）。

### 5.3 JSON 出力

- JSON にも各ゲームの broadcasters 辞書を保存する。

## 6. 表示・出力への制約

- 判定ロジックはランキングや平均比較の計算には影響しない。HTMLの列と表示対象は[デザイン仕様](report-design.md)に従う。
- 判定（3.1–3.5）は HTML、メール plain / HTML / 添付で共通使用する。
- 21 / 23 の時間帯ルールは維持する。
- 表示対象の時間帯では「単一配信者による急増」枠は該当なしの場合に非表示とする。21時・23時のHTMLでは候補の有無にかかわらず時間帯別の枠全体を非表示とする。

## 7. 非目標

- 観測範囲外の配信者の実視聴者数の推定。
- 内訳欠測からの補間・移行。
- 判定ロジックによるランキング・平均比較の計算変更。
