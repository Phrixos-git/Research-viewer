# 保存済みテストデータによるE2E

## 対象

`python3 e2e.py` で、2026-11-07（JST）までの `data/YYYY-MM-DD/HH.json` を読み、SQLite復元、期間平均・順位比較、JSON/HTML出力、メール本文と添付の検証を一括実行する。正式開始日以降の記録は入力に含めない。保存JSONはゲーム別集計済みなので、Twitchからの取得・配信別からゲーム別への再集計・日本語フィルターの実通信はこのE2Eの対象外。

- 通常実行はネットワーク通信も実メール送信も行わない。保存済みデータを主シナリオに使用する。足りないケースは別の合成シナリオとして追加し、元の取得記録の人数・内訳には補完しない。
- 読み込んだJSONと通常SQLite・HTML・メール設定・送信履歴は変更しない。毎回 `.local/e2e-*` に独立したSQLite、JSON、HTML、検証結果とメールを保存する。GitHubへのpushは行わない。
- 最新の23時のテスト記録をメール対象とする。前日記録があれば増加率Top10・平均増減・順位マークを検証する。人数・率・順位の期待値は保存データから独立計算する。
- メールのHTML本文・添付・出力HTMLが一致し、上位100タイトル・Top10・時間別比較非表示・矢印色・テスト表示を確認してから送信する。
- `python3 e2e.py --send` で最後に1通だけ実送信する。送信先は **kurahasb@gmail.com** に固定し、通常設定の宛先は使用しない。保存済みGmail設定から送信元と認証情報を利用し、設定ファイルを書き換えない。
- 件名とテキスト本文にE2Eテストであることを明記し、Message-IDは実行ごとに別にする。HTMLには全言語のテストデータである旨が表示される。
- 結果は作業フォルダーの `result.json`、送信内容は `message.eml` に保存する。認証情報は成果物・ログに保存しない。作業フォルダーとメールファイルは本人だけが読み書きできる権限とする。
- SMTPの成功はサーバー受付の確認であり受信箱への到着・実際の描画の確認ではない。受付状況が不明な失敗は自動再送しない。

## 不足ケースの合成データ

`.local/e2e-*/supplemental/` に、全タイトル名を `[合成]` で始めた2日×5時間のデータを生成する。0人からの増加、0人のまま、横ばい、減少、増加率同率、部分集計、新規タイトル、通常の急上昇、単一配信者による急増、配信者内訳なしを含む。SQLite復元、比較・HTML・テキスト本文・添付まで検証し、合成シナリオのメールは模擬送信のみとする。実送信は保存済みデータの主シナリオ1通だけ。

20時・22時には直前の時間帯から増える合成データを入れ、通常の急上昇（400人増・100％増）と単一配信者による急増（300人増・60％増）のカード、分類、配信者内訳を検証する。各HTMLを `supplemental/output/2026-11-06/20.html` と `22.html` に保存する。21時・23時では急上昇カードが非表示のままであることと、23時メールのテキスト本文では19〜23時の各時間帯に通常枠・単一枠が掲載されることも確認する。

## 実行

```bash
python3 -m unittest discover -s tests -q
python3 e2e.py
python3 e2e.py --send
```

実送信は最後のコマンドを明示的に実行した場合のみ。通常の自動テストでは実送信しない。
