# 視聴報告HTMLデザイン仕様

## 制約（前提）
- `render_html` はメールHTML本文と添付HTMLに共用されるため、メールクライアント互換を最優先する。
- 外部フォント・JavaScriptは使用しない。フォントは日本語対応のシステムフォントを指定する（`"Hiragino Sans","Noto Sans JP","Yu Gothic UI",system-ui,sans-serif`）。
- 取得・集計・比較ロジック（Python側）は変更しない。

## 実装方針: インラインCSS中心
- 基本デザインは**styleタグなし・CSS変数なし**でも成立するよう、要素ごとにインライン`style`属性で記述する。
- 外枠テーブルの`bgcolor`属性と`role="presentation"`を維持する。データ表の`scope`属性を維持し、データ表にはpresentationロールを付けない。
- 既存styleタグを維持し、600px以下の画面調整をmedia queryで補強する。基本デザインとバーの幅はインライン指定し、CSS変数には依存しない。

## 配色
- グラデーション: `#5b4a9e` → `#90e0bc33`
- グラデーション非対応環境向けの単色fallback（`#5b4a9e`）をbgcolor等で必ず併記する。

## 共通スタイル
- 行高: `line-height: 1.4`
- 数値列: `font-variant-numeric: tabular-nums` で桁を揃える。
- ヘッダ行: `position: sticky` で固定し、下辺にshadow（`box-shadow`）を表示。

## ランキング
- ランキング表とメールのタイトル一覧は同時視聴者数順の上位100件まで表示する。取得・集計・保存データは全件を保持し、順位の並び替えや既存の急上昇判定は変えない。タイトル数は表示件数と集計件数を区別して示す。23時だけ右端に前日の23時との順位変動欄を追加する。前日の全保存ゲームをIDで照合し、同順位は「-」、順位上昇は「↑」、下降は「↓」、前日に同じIDがない場合は「★」。101位以下からの上位100件へのランクインも「↑」とする。ユーザー指定により、前日の記録自体がない場合も「★」を表示する。
- 23時だけ、同時視聴者数列と右端の順位前日比列の間（右から2列目）に「19〜23時平均の前日増減（人）」を表示する。既存の期間平均計算を使い、同じゲームIDで両日に存在する同時刻の組だけを比較する。欠測を0で補完しない。符号付き小数1桁と比較件数/予定5件を表示し、比較できないタイトルは「比較データなし」とする。件数不足は部分集計である旨を注記する。他の時間にはこの列を表示しない。
- 装飾バーの幅は `round(sqrt(viewers / max) * 100)` で計算。
  - 正の値は最低 **2%**、最大 **100%** をクランプ。
  - 0人のバー幅は0%。maxがゼロでも除算せず、空リストも安全に表示する。
- バー要素は `aria-hidden="true"` の装飾要素とし、隣に実数（視聴者数）を併記する。
- 視聴者数セルは左に実数、右にバーの順で表示する。実数は左側の残り幅で右寄せ、バーは全行で共通幅の領域内に左揃えとし、数字の桁数で開始位置をずらさない。モバイルでは引き続き数値の下に4pxのバーを表示する。平方根スケールと順位・前日比は変更しない。
- 順位前日比の「↑」は赤系 `#ff8a9a`、「↓」は青系 `#80bfff` をセルのインラインCSSで指定する。「★」は黄色系 `#ffd166`、「-」は標準色を使う。
- 同時視聴者数の見出しは数値領域の真上に置く。見出しにも本文と同じ幅のバー用空白領域を設け、数値とバーの間隔は16pxにする。600px以下では見出しの空白を非表示にし、数値下のバーとの間隔は既存の4pxを維持する。
- 上位3位はバッジ表示＋行背景色で強調。
- 順位列は4.5emの幅・最小幅で中央揃えにし、セルとバッジは折り返さない。表の最大幅100%と視聴者数・バーの配置は維持し、順位列を広げた分はタイトル列の折り返しで吸収する。タイトルには最小幅を設けず、長い名前は折り返す。
- mobile（600px以下）: バーの高さを 4px にし、数値の下に配置する。

## 前日比較
- 比較表の人数列は「前回（M/D）」「今回（M/D）」と表示する。日付はレポートのJST日時から求め、21時・23時の前日比較では前日と当日、通常時間帯の直前比較では直前と今回の日付を使う。モバイルの項目名・メールHTML本文・添付HTMLにも同じ表示を使う。
- 23時の「両日の19〜23時の平均同時視聴者数」比較表は、増減率が算出できる全タイトルから増加率の降順で最大10件（Top10）を表示する。同率はゲームID順。比較元0人で率が算出できないタイトルは対象外。減少・横ばいも率順の対象とし、10件未満なら存在する件数だけ表示する。21時の比較表と通常時間帯の直前比較は従来どおり。タイトルランキングの平均増減列にはTop10に絞る前の全比較結果を使う。
- 21時・23時のHTMLでは各時間帯の前日比較セクション（急上昇・単一配信者枠・判定不可注記）を表示しない。期間平均の前日比較表は維持する。19・20・22時の直前比較は維持する。メールHTML本文と添付も同じ表示とし、メールのテキスト本文は時間帯別比較を維持する。
- 急上昇は[配信者別判定仕様](streamer-rises.md)に従い、全体と最多寄与配信者の除外後とも25％以上の通常枠と、単一配信者による急増枠に分ける。内訳未取得は判定不可。単一枠は該当時間帯だけ表示し、ID・寄与率・除外後人数を併記する。
- 比較`rows`なしの場合: **21時・23時のみ**「急上昇」「平均比較」セクションを隠し、メタ情報の下に「蓄積中」ノート1行を表示。
- 比較ありの場合は期間平均表を表示する。通常（21/23時以外）は直前比較と急上昇表示を維持する。
- mobile（600px以下）: 既存のcomparison用mobileルールを維持（変更しない）。

## 取得範囲とテストデータ
- 2026-11-08（JST）以降は日本語配信上位最大1,000件から集計し、HTMLとメールの取得範囲に日本語配信と明記する。所在地による制限ではない。
- 2026-11-07までの記録は全言語のテストデータとしてHTML冒頭に表示する。正式・テストの境界をまたぐ平均比較・直前比較・急上昇・順位比較は禁止する。
- 正式実行時の出力とメール再送対象は正式履歴のみ。開始日前は通常収集をスキップする。

## メタとfooter
- 冒頭にタイトル数・ゲーム集計対象配信数・日時JSTのpillを表示し、取得配信数（最大1,000件）も保持する。開始・終了時刻だけを既存注記を保持したfooterへ移動する。

## テスト方針
- 空リスト・0視聴・比較rowsなし(21時/23時/それ以外)・比較ありの各ケースでHTML出力を検証する。

## Ocarinaの同名表示調査

2026-11-05 23時の保存JSONでは、5位58,687人はTwitchゲームID `2067181260`、34位3,840人は `11557`。集約キーはTwitchゲームIDであり、名前やIGDB IDではない。IGDB IDの有無でゲーム対象を判定するが、その値自体は保存していないため、両IDのIGDB対応関係は保存記録からは確認できない。同名の別IDが別行になるためで、HTMLによる二重描画ではない。今回データや集約を変更しない。表示上区別する案として、同名の場合だけTwitchゲームIDを補記する方法がある（今回は未実装）。
